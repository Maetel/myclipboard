# 마이메모 클립보드 사용자 시나리오와 검증 기록

이 문서는 `memos.my` 웹과 MyMemo Clipboard Windows 앱 사이에서 사용자가 실제로 겪는 흐름, 기대 결과, 검증 방법을 함께 기록합니다. 정상 흐름만 확인하지 않고 네트워크 끊김, 중복 조작, 취소, 세션 폐기, 원본 변경처럼 데이터나 사용자의 의도와 다른 결과를 만들 수 있는 경계도 완료 조건에 포함합니다.

## 검증 결과를 읽는 기준

- **실기기**: 설치된 Windows 앱과 운영 `memos.my`를 실제로 조작해 결과를 확인했습니다.
- **자동화**: TypeScript·Rust·정적 회귀 테스트로 같은 결함이 다시 들어오지 않는지 확인했습니다.
- **코드 확인**: 구현과 서버 검증 규칙을 양쪽에서 대조했습니다. 이것만으로 실기기 완료를 주장하지 않습니다.
- 운영 계정의 비밀번호, 세션 원문, 암호화 키와 클립보드 원문은 검증 기록에 남기지 않습니다.
- 임시 계정·파일·전송 요청은 검증 뒤 삭제하고 계정·세션·항목·이벤트가 남지 않았는지 확인합니다.

## 기본 사용자 흐름

### S1. 가입과 첫 로그인

1. 사용자는 `memos.my/login`에서 자유롭게 가입합니다.
2. Windows 앱에서 같은 아이디와 비밀번호로 로그인합니다.
3. 앱 전용 세션만 Windows 사용자 보안 저장소에 남고 비밀번호는 저장하지 않습니다.
4. 웹의 **기기 간 클립보드**에서 현재 기기를 확인하고 필요하면 해당 기기만 로그아웃할 수 있습니다.
5. 일반 계정은 메모 파일과 클립보드 기록을 합쳐 50MiB까지 저장합니다. exact login `stan`은 사용량은 표시하되 상한을 적용하지 않습니다.

기대 결과는 웹과 앱이 `smallmemo_accounts.id` 하나를 사용자 기준으로 쓰고, 웹 cookie와 앱 `smc_` 세션을 섞지 않는 것입니다. 예전 `admin.memos.my` 설정은 옛 로컬 기록과 세션을 정리한 뒤 같은 마이메모 계정으로 한 번 다시 로그인하도록 안내합니다.

### S2. 텍스트와 링크 복사

1. 텍스트나 HTTP(S) 링크를 복사하면 현재 기기의 암호화된 로컬 기록에 먼저 들어갑니다.
2. 온라인이면 같은 event ID로 마이메모에 게시되고 웹과 다른 기기에서 한 번만 보입니다.
3. 네트워크가 끊기면 암호화된 전송 대기열에 남습니다.
4. 다음 복사, 수동 동기화, 기록 창 열기 또는 앱 재시작 뒤 연결 복구에서 같은 event ID로 재전송합니다.

기대 결과는 오프라인 항목의 순서가 유지되고, 응답 손실이나 반복 재시도에도 중복이 생기지 않는 것입니다.

### S3. 이미지와 일반 파일 하나 공유

1. 이미지 또는 10MiB 이하 일반 파일 하나를 복사하면 파일명·크기·형식과 이미지 썸네일만 기록에 게시합니다.
2. 일반 파일 원본은 다른 기기에서 항목을 선택하기 전에는 읽거나 업로드하지 않습니다.
3. 폴더, 여러 파일, 0바이트 파일과 10MiB 초과 파일은 경로를 훑거나 재귀 탐색하지 않고 거부합니다.
4. 다른 기기에서 선택하면 원본 기기가 제한 시간 안에 실제 bytes를 보내고, 서버와 받는 앱이 크기와 SHA-256을 모두 확인합니다.
5. 검증이 끝난 bytes만 Clipboard에 적용합니다. 실패하거나 취소하면 기존 Clipboard와 원본 파일을 바꾸지 않습니다.

### S4. 기록 창에서 검색·선택·취소

1. 사용자가 붙여넣을 앱을 앞에 둔 채 저장된 단축키를 누르면 기록 창이 열리고 검색창에 초점이 갑니다.
2. 방향키는 선택만 옮깁니다. Enter 또는 항목 클릭만 선택한 내용을 Clipboard에 적용하고, 기록 창을 열기 직전의 앱으로 붙여넣기를 한 번 시도합니다.
3. Escape 또는 기록 창 밖 클릭은 선택 전에는 아무 내용도 적용하지 않고 닫습니다.
4. 파일을 받는 중 Escape를 누르면 요청을 취소하고, 늦게 응답이 도착해도 Clipboard를 바꾸거나 뒤늦게 붙여넣지 않습니다.
5. 더블클릭, Enter 연타, 클릭과 Enter가 겹쳐도 한 시점에는 선택 하나만 실행합니다.
6. 검색·파일 받기·붙여넣기가 실패하면 오류를 짧게 알리고 검색 초점을 복원해 다시 선택할 수 있게 합니다.
7. 새 기록이 없거나 동기화 결과가 같으면 목록, 검색어, 현재 선택과 scroll 위치를 다시 만들지 않습니다.

기록 창은 검색 입력에 연결된 listbox와 현재 선택을 보조 기술에 전달합니다. 내부 기기 ID 같은 진단값은 기본 화면에 노출하지 않습니다. 설정 화면의 안내에는 기본값을 고정 표시하지 않고 사용자가 저장한 실제 단축키를 표시합니다.

### S5. 로그아웃·세션 폐기·용량 초과

- 앱에서 로그아웃하거나 동기화를 끄면 이 기기의 세션, 로컬 기록, 전송 대기열과 암호화 키를 지웁니다. 다른 기기와 서버 기록은 유지합니다.
- 웹에서 기기를 로그아웃하면 다음 동기화뿐 아니라 복사 게시, 썸네일 읽기, 파일 요청·상태 확인·다운로드에서 받은 401도 즉시 같은 정리 흐름으로 처리합니다.
- 50MiB를 넘는 새 영구 기록은 저장하지 않고 기존 기록은 그대로 둡니다. 앱은 웹에서 파일이나 기록을 정리하도록 안내하며 같은 event ID를 로컬 대기열에 유지합니다.
- 비밀번호를 바꾸면 현재 기기를 제외한 다른 앱 세션이 폐기되고, 폐기된 기기는 다음 요청에서 다시 로그인하도록 안내합니다.

### S6. 재시작과 유휴 상태

- 앱 재시작과 Windows 재로그인 뒤에도 인스턴스는 하나만 실행되고 보이는 console 창이 없어야 합니다.
- 유휴 상태에서는 Clipboard를 열거나 서버를 polling하지 않습니다. 복사 알림, 기록 창 열기, 수동 동기화처럼 사용자가 만든 사건에서만 작업합니다.
- 원격 요청을 받을 수 있는 로컬 파일 원본이 있을 때만 제한된 주기로 요청 상태를 확인합니다.

## fresh-context 비판 검토에서 보강한 경계

기존 검증은 “선택하면 성공한다”와 “선택 전에 취소한다”를 각각 확인했지만, 두 사건이 겹치는 경우를 확인하지 않았습니다. 특히 원격 파일 대기 중 기록 창을 닫아도 기존 구현은 최대 45초 뒤 다운로드를 계속해 사용자가 다른 작업을 하는 화면에 늦게 붙여넣을 수 있었고, 더블클릭이나 Enter·클릭 중복 입력은 파일 요청과 붙여넣기를 두 번 만들 수 있었습니다.

0.2.2에서는 popup open/close와 진행 중 선택을 하나의 상태로 묶었습니다. 선택은 한 번에 하나만 시작하고, Escape·바깥 클릭·로그아웃으로 창이 닫히면 진행 중 전송의 각 대기·상태 확인·다운로드·Clipboard 적용 경계에서 취소를 다시 확인합니다. UI도 진행 중 추가 입력을 막고 “Esc를 누르면 취소”를 바로 표시합니다.

같은 검토에서 다음 사용성 문제도 함께 고쳤습니다.

- 폐기된 세션이 썸네일이나 파일 전송 경로에서 발견돼도 숫자 상태 코드만 보여 주던 흐름을 통일해, 즉시 로컬 비밀 데이터를 정리하고 다시 로그인을 안내합니다.
- 검색 결과의 선택을 `aria-activedescendant`로 전달하고 상태 변화를 live region으로 알립니다.
- 진단용 기기 ID 뒷자리를 목록에서 제거하고 파일명도 검색 대상에 포함했습니다.
- 사용자가 단축키를 바꿔도 기본 단축키만 안내하던 문구를 저장된 실제 값으로 바꿨습니다.

## Windows 릴리스 완료 기준

1. `npm run typecheck`, `npm run build`, `npm run test:windows-idle`이 통과합니다.
2. Windows native Rust unit test와 release/NSIS build가 통과합니다.
3. 설치본의 ProductVersion과 SHA-256을 확인하고 실제 실행 파일 경로의 process가 하나인지 확인합니다.
4. V9와 V10을 설치본에서 반복해 취소 뒤 지연 붙여넣기 0회, 중복 붙여넣기 0회를 확인합니다.
5. V5의 직접 401 경로와 V8의 변경된 원본 거부를 확인합니다.
6. 최종 설치본에서도 짧은 유휴 측정으로 network·Clipboard open·state write가 다시 생기지 않았는지 확인합니다.
7. 임시 계정, 파일, 요청과 테스트 도구를 정리하고 원격 `main`과 릴리스 commit을 일치시킵니다.
